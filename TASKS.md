# bitrix-lab — локальный стенд 1С-Битрикс + Битрикс24 для практики D7 (решение Павла 22.10.2026)

Зачем: вакансии Битрикс (Kit 138745196 и подобные) упираются в Bitrix Framework D7: ORM, инфоблоки, свои модули, события,
тегированный кеш, интернет-магазин, обмен с 1С, коробка на сервере. Делаем стенд на Mac и закрываем эти пункты проектами,
которые потом можно показать (GitHub + описание в резюме/на mvp-code.ru).

Окружение: Docker Desktop (на Mac есть, демон сейчас не запущен), 16 ГБ RAM, ~76 ГБ свободно.
Дистрибутив: пробная версия 1С-Битрикс: Управление сайтом (редакция «Бизнес» — интернет-магазин) с 1c-bitrix.ru
через bitrixsetup.php; Битрикс24 — бесплатный облачный портал для REST-приложений.

## План (каждый шаг → проверка)
1. Стенд: docker-compose (nginx + PHP-FPM 8.x + MariaDB + Redis/memcached) под требования Битрикса, «Проверка системы» без ошибок.
2. Установка БУС «Бизнес» + демо интернет-магазина. Проверка: каталог, корзина, заказ проходят.
3. Свой модуль на D7 (`mvpcode.leads`): ORM-сущность (таблица заявок), миграция при установке/удалении,
   обработчики событий (OnSaleOrderSaved → запись), агент по расписанию, страница в админке. Проверка: установка/удаление чистые.
4. Тегированный кеш: компонент «популярные товары» с кешем по тегу инфоблока, сброс при изменении товара. Проверка: время и сброс.
5. Интернет-магазин: правило скидок, склады и остатки, статусы заказа. Обмен с 1С через CommerceML (опора: ~/Projects/cml-bridge).
6. Доработка стандартного компонента через свой шаблон и result_modifier, без правки ядра (безопасное обновление).
7. Битрикс24: облачный портал + локальное REST-приложение: заказ с сайта → сделка с источником/UTM, смарт-процесс,
   робот/бизнес-процесс. Проверка на живом портале.
8. Упаковка: репозиторий github.com/mvpcodego/bitrix-lab (модуль + шаблоны + docker-compose + README), строки в резюме
   «Интегратор Битрикс24», кейс на mvp-code.ru.

Правила: ядро Битрикса не править; ключи и пароли только в .env (в .gitignore); код модуля — PSR-4, D7 ORM.
